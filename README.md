# MLP Translation

面向小说英译中的双栏翻译网页。左侧输入原文，右侧显示并编辑译文，通过专名表和风格配置控制翻译结果。

## 当前状态

项目已建库，当前只有需求说明，尚未实现翻译功能或部署 GitHub Pages。

## 第一版范围

- 左右双栏：粘贴或导入原文，显示译文并允许手动修改。
- 翻译与停止操作，以及复制、导出译文。
- 专名表：添加、编辑和导入英文词条、指定译名、别名及使用说明。
- 风格配置：规划 MLP-BA、贝多芬及自定义配置，使用核对过的双语样例辅助翻译。
- 模型设置：配置 API 地址、模型名称与使用者自己的 API Key。
- 基本检查：提示专名不一致和输出中断；专名匹配需要区分普通词义与专名含义。
- 在浏览器本地保存专名表和风格配置。

翻译历史、账号系统、数据库、后台长篇任务和桌面安装包不作为第一版必需功能。

## 技术与部署方向

采用 HTML、CSS 和 JavaScript 构建纯前端网页，代码托管于 GitHub，计划通过 GitHub Pages 发布。具体构建工具待实现阶段确定。

先验证所选模型 API 是否支持浏览器跨域调用。支持时由浏览器直接请求；不支持时再评估独立后端代理，GitHub Pages 本身不能运行该代理。纯前端版本不保证关闭页面后继续翻译。

## 数据与密钥

- API Key 由使用者输入，默认仅保存在当前页面内存中，不提交到仓库、不写入构建产物或日志。
- 原文及相关专名、风格样例会发送到使用者配置的模型服务，应在请求前明确显示目标服务。
- 小说原文、完整译文、个人配置和凭据不随代码发布。
- 专名表和风格配置的本地存储不等于云端同步，应支持导出备份。

## 实现顺序

1. 完成双栏界面和可编辑译文区。
2. 实现专名表与风格配置的编辑、导入及本地保存。
3. 验证模型接口直连，接入翻译、停止和错误提示。
4. 添加专名检查、复制和导出。
5. 使用已核对的双语片段验证结果，再部署 GitHub Pages。

## 风格资料准备

参考作品的中文风格观察目前属于抽样结论，仍需与英文原文对齐核验。作品风格和人物口吻分别管理；简繁混用、缺字及标点错误不作为模仿目标。参考材料和双语样例的公开发布范围需另行确认。
